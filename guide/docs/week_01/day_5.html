DAY 5 · ENCODING AND SERVINGMLDSAAISys

From a trained merge list to a production tokenizer

Algorithms · the fast encoder and caches

The main-reading encoder scans the chunk for the lowest-rank pair, merges all its occurrences, and repeats: O(L · R) per chunk, where R is the number of distinct merges that apply. Chunks are short, so this is fine, until a chunk is long. A 10 KB string with no spaces needed 428 rounds.

The fix uses a doubly linked list of tokens and a min-heap of (rank, position) for adjacent pairs. Pop the lowest rank; if the entry is stale, skip it; otherwise splice the two nodes and push only the two new neighbouring pairs.

L⇄A⇄B⇄R  →  L⇄AB⇄R
push:(rank(L, AB), L)(rank(AB, R), AB) B is marked dead; entries pointing at it become stale
O(1) splice, O(log L) heap work per merge, so O(L log L) per chunk.
10 KB chunk (Alice with spaces removed), 2,000-token vocabulary, identical output
rescan encoder0.31 s
linked list + heap0.005 s

Two more speed-ups matter in practice: a chunk cache (natural text repeats, so most chunks hit), bounded so unique strings can't exhaust memory, and a compiled hot loop (tiktoken and Hugging Face tokenizers are in Rust).

146 · LRU cache
class Node:
    __slots__ = ("key", "val", "prev", "next")
    def __init__(self, key=0, val=0):
        self.key, self.val, self.prev, self.next = key, val, None, None

class LRUCache:
    def __init__(self, capacity):
        self.cap, self.map = capacity, {}
        self.head, self.tail = Node(), Node()            # sentinels: no edge cases
        self.head.next, self.tail.prev = self.tail, self.head
    def _remove(self, n):
        n.prev.next, n.next.prev = n.next, n.prev
    def _push_front(self, n):
        n.prev, n.next = self.head, self.head.next
        self.head.next.prev = n; self.head.next = n
    def get(self, key):
        if key not in self.map: return -1
        n = self.map[key]; self._remove(n); self._push_front(n)
        return n.val
    def put(self, key, value):
        if key in self.map: self._remove(self.map[key])
        n = Node(key, value); self.map[key] = n; self._push_front(n)
        if len(self.map) > self.cap:
            lru = self.tail.prev; self._remove(lru); del self.map[lru.key]
bpe.py · O(L log L) encoder
def encode_chunk_fast(data, ranks):                  # ranks: pair -> new id (= rank order)
    ids = list(data); n = len(ids)
    if n < 2: return ids
    prev = list(range(-1, n - 1)); nxt = list(range(1, n + 1)); nxt[-1] = -1
    alive = [True] * n
    heap = [(ranks[(ids[i], ids[i + 1])], i) for i in range(n - 1) if (ids[i], ids[i + 1]) in ranks]
    heapq.heapify(heap)
    while heap:
        r, i = heapq.heappop(heap)
        j = nxt[i]
        if not alive[i] or j == -1 or ranks.get((ids[i], ids[j])) != r:
            continue                                     # stale entry
        ids[i] = r; alive[j] = False                     # i absorbs j
        nxt[i] = nxt[j]
        if nxt[j] != -1: prev[nxt[j]] = i
        for a in (prev[i], i):                           # the two new neighbouring pairs
            if a != -1 and nxt[a] != -1 and (ids[a], ids[nxt[a]]) in ranks:
                heapq.heappush(heap, (ranks[(ids[a], ids[nxt[a]])], a))
    out, i = [], 0
    while i != -1:
        out.append(ids[i]); i = nxt[i]
    return out

Why the order matches the simple encoder: equal ranks pop left to right (the position is the second tuple field), and a newly created pair always has a higher rank than the merge that created it, because its token was learned later.

ML · failure modes and alternatives
  • Glitch tokens. SolidGoldMagikarp became a GPT-2 token because it was frequent in the tokenizer's training data but almost absent from the model's. Its vector stayed near its random start, and the model behaved strangely on it.
  • Spelling and counting letters. The model never sees the letters inside strawberry, so "how many r's?" asks about something it never observed directly.
  • Prompt boundaries. A prompt ending mid-word ("https:") splits differently from the same text in training. "Token healing" backs up one token and constrains the next.
  • Digits. GPT-2 merges digits however training happened to; later patterns cap groups at 3, which makes arithmetic easier to learn.

BPE-dropout randomly skips merges while the model trains, so it sees a word's pieces, not just one fixed split, and becomes more robust to typos.

Solution
bpe.py · BPE-dropout
def encode_dropout(data, ranks, p, rng):
    ids = list(data)
    while len(ids) >= 2:
        cands = [(ranks[q], q) for q in zip(ids, ids[1:]) if q in ranks and rng.random() >= p]
        if not cands:
            break
        r, pair = min(cands)
        ids = merge(ids, pair, r)
    return ids
# p = 0.3, vocab 2,000 on Alice, five seeds:
#  ' un|ha|pp|iness'   ' un|ha|pp|ine|ss'   ' u|n|ha|pp|iness'   ' un|ha|p|p|in|es|s'   ...

With p = 0 it is ordinary BPE; with p = 1 it returns bytes. Use it only while training the model; at inference, encode deterministically.

Design · training on terabytes, serving at scale

Prompt: train a tokenizer on a 10 TB multilingual corpus, then serve encoding for an API handling 50,000 requests per second.

shard 1chunk + count
shard nchunk + count
↓ map (parallel)
reduce: sum countersthen drop chunks seen fewer than a few times
↓ one machine
merge loopsequential: each merge depends on the last
↓
merges file + hashshipped with the model; checked at load
Counting is word count, the classic MapReduce job. The merge loop would need a global barrier per merge (200,000 for a 200k vocabulary), so it isn't distributed; after deduplication it fits on one machine.
EstimateValueWorking
Chunks in the corpus≈ 2 × 101210 TB ÷ ~5 bytes per chunk

Merge-loop memory≈ 5–10 GB108 × (~10 ids × 4 bytes + index overhead), compact language

Serving: tokenize in the API layer, before the GPU queue (the count is needed for routing, rate limits and billing); compiled code plus a bounded chunk cache. The tokenizer is part of the model's contract: token ids are baked into the embedding table, so ship the merges file with the model, store its hash, refuse a mismatch, and pin the regex and Unicode versions.

Solution
count.py · map and reduce
from collections import Counter
from multiprocessing import Pool

def map_shard(lines):
    return Counter(c for line in lines for c in PATTERN.findall(line))

def reduce_counts(counters):
    total = Counter()
    for c in counters:
        total.update(c)
    return total

lines = open("data/alice.txt").read().splitlines()
with Pool(4) as pool:
    total = reduce_counts(pool.map(map_shard, [lines[i::4] for i in range(4)]))
assert total == map_shard(lines)                  # same counter as one pass

Fleet sizing: if one core encodes t tokens/s on real traffic (measure it; the cache hit rate dominates), the fleet needs 5 × 107 / t cores, plus headroom for peaks (×2) and failures (+1 zone). Mismatch detection: the model's config stores the SHA-256 of the merges file; the server hashes the tokenizer it loads and refuses to start on a difference.
