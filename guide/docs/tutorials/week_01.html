Tokens and Decoding

A language model only ever scores the next token. What a token is, which one gets picked, and whether the output parses are all decided by code around the model. This week you write that code.

Each section: the idea in plain words, the code, something to try, what goes wrong, and where to read more. The Fundamentals panels give the DSA, ML and design idea underneath each concept, with a deeper read and practice problems. The Talk boxes are the lecture plan: time, what to show, what to ask the room. The lab is in week_01/; the code here shows the idea, not the full lab solution.

THE PROBLEMread first

Valid JSON, every time, in English and Hindi

A support team wants every incoming ticket turned into a JSON record, for example {"lang":"hi","priority":"high","tags":["refund"],"text":"मेरा रिफंड अभी तक नहीं आया"}, by a language model. Two things go wrong straight away:

  • Some answers do not parse. A missing quote or a trailing comma breaks the pipeline, and retrying has no upper bound.
  • Hindi costs more. The same ticket in Hindi uses several times more tokens, so it is slower and pricier.

Neither is the model's fault. Both are decided by code around it: the tokenizer before it and the decoder after it. This week you build both, with a small counting model in the middle, and end with output that is valid by construction.

01 · BYTES AND UTF-8
AI5 min

Start from bytes, and nothing is ever unknown

Every string is a sequence of bytes in UTF-8. If the vocabulary starts with all 256 byte values, any text can be encoded, in any language, with no "unknown" token.

UTF-8 uses 1 byte for ASCII and 2–4 bytes for everything else. The first byte says how many follow:

Fundamentals behind this section
DSA · Bits and prefix codes

UTF-8 is a prefix code: the leading bits of the first byte say how long the character is, so a reader never needs to look ahead. Checking a byte is a mask-and-compare: (b & 0b1110_0000) == 0b1100_0000 means "2-byte lead".

02 · BPE TRAINING
AIDSA10 min

Merge the most common pair, again and again

Byte-pair encoding starts with single bytes and repeatedly glues together the pair of neighbours that appears most often. Each glue becomes a new token. Stop when the vocabulary is big enough.

def merge(ids, pair, new_id):
    """Replace every non-overlapping occurrence of pair, left to right."""
    out, i = [], 0
    while i < len(ids):
        if i + 1 < len(ids) and (ids[i], ids[i + 1]) == pair:
            out.append(new_id); i += 2          # skip both: "aaa" → [aa, a], not [aa, aa]
        else:
            out.append(ids[i]); i += 1
    return out

def train_naive(text, vocab_size):
    ids, merges = list(text.encode("utf-8")), []
    while 256 + len(merges) < vocab_size:
        counts = Counter(zip(ids, ids[1:]))
        if not counts: break
        best = min(counts, key=lambda p: (-counts[p], p))   # most frequent; ties → smallest pair
        if counts[best] < 2: break
        merges.append(best)
        ids = merge(ids, best, 255 + len(merges))
    return merges

Real tokenizers first split text into chunks (words, numbers, punctuation, spaces) with a regex and never merge across chunks, so "dog." and "dog" share a token. The lab uses GPT-2's pattern for that.

DSA · Hash maps and counting

A hash map turns a key into an array slot, so insert and lookup are O(1) on average. Counter(zip(ids, ids[1:])) is a hash map from pair to count: one pass, O(n). BPE is "count, take the best, repeat".

03 · THE MERGE HEAP
DSA10 min

Don't re-count: update, and let a heap find the best

A merge only changes the words that contain the merged pair. Keep pair counts in a hash map, update just those words, and keep a heap to find the most frequent pair. When a count changes, don't search the heap for the old entry: push a new one and ignore stale entries when they reach the top.

heap = [(-count, pair) for pair, count in pair_counts.items()]
heapq.heapify(heap)                       # (-count, pair): biggest count first, then smallest pair
while need_more_merges and heap:
    neg, pair = heapq.heappop(heap)
    if pair_counts.get(pair, 0) != -neg:  # stale: the count changed after this was pushed
        if pair_counts.get(pair, 0) > 0:
            heapq.heappush(heap, (-pair_counts[pair], pair))
        continue
    # ... merge pair inside the words listed in where[pair] only,
    #     add the count deltas to pair_counts, push each changed pair again

Fundamentals behind this section
DSA · The binary heap

A heap is a binary tree stored in an array: the children of index i are 2i+1 and 2i+2, and every parent is ≤ its children. Push and pop are O(log n) (sift up, sift down); heapify is O(n). Python's heapq is a min-heap, so store -count to get the max.

Lazy deletion: a heap cannot cheaply find and update an entry. Instead, push the new value and skip stale ones when they surface. Every "update a priority" problem (Dijkstra included) uses this trick.

Deeper VisuAlgo heap (animated) · heapq docs

Design · Incremental over recompute

The principle here is general: when a small part of the input changes, update the small part of the answer. The same idea runs materialized views, incremental builds and streaming aggregates.

Watch out
  • The tie-break must live in the heap key too, or the heap and the naive spec disagree on ties.
  • A word can contain the merged pair twice: count deltas per word, not per occurrence found.

04 · ENCODE BY RANK
AI5 min

Encoding replays training, in merge order

To encode new text, repeat: find the pair in this chunk that was merged earliest in training, and merge it. The merge list is the tokenizer.

def encode_chunk(data: bytes, ranks: dict) -> list[int]:
    ids = list(data)
    while len(ids) >= 2:
        pair = min(zip(ids, ids[1:]), key=lambda p: ranks.get(p, float("inf")))
        if pair not in ranks: break                  # nothing left to merge
        ids = merge(ids, pair, ranks[pair])
    return ids

def decode(ids):
    return b"".join(vocab[i] for i in ids).decode("utf-8", errors="replace")

Fundamentals behind this section
DSA · Memoization and caching

Real text repeats the same chunks (" the", " and"), so encode each distinct chunk once and remember the result: a dict from chunk to ids. Bound it, or memory grows with the corpus. An LRU cache is the standard bounded choice.

Practice LC 146 · LRU Cache

Design · IDs that stay stable

Token ids are a contract with every model trained on them: change a merge and every id after it shifts. That is why save writes a format_version. Stable, versioned identifiers are the same problem as this week's unique ID generator rep.

Watch out
  • Encoding by frequency in the new text instead of rank gives different ids from training. Ranks only.
  • Cache each chunk's ids: real text repeats the same words constantly.
05 · COUNTING IS A MODEL
ML8 min

The simplest language model counts what came next

An n-gram model predicts the next token from the last n − 1 tokens by counting how often each token followed them in training. Counting is not a shortcut: it is exactly the maximum-likelihood answer.

P(w | ctx) = (count(ctx, w) + k) / (count(ctx) + k · V)     # add-k smoothing

def logprobs(self, context):
    ctx = self._context(context)                      # last n-1 ids, padded with BOS
    denom = self.totals[ctx] + self.k * self.vocab_size
    out = [log(self.k / denom)] * self.vocab_size     # every unseen token gets k
    for token, c in self.counts[ctx].items():         # only the seen ones need work
        out[token] = log((c + self.k) / denom)
    return out

Why counts? Maximise Σ cw log pw subject to Σ pw = 1. A Lagrange multiplier gives pw = cw / Σ c. Smoothing adds k imaginary counts to every token, so nothing has probability 0.

Fundamentals behind this section
ML · Maximum likelihood

Pick the parameters that make the training data most probable. For a categorical distribution with counts cw, maximise Σ cw log pw with Σ pw = 1: the answer is pw = cw/Σc. Add-k smoothing is the same estimate after adding k pseudo-counts (a Dirichlet prior).

Practice Kaggle LLM - Detect AI Generated Text: fit one n-gram model on human essays and one on AI essays, and score each essay by the log-likelihood ratio. That is naive Bayes built from this exact code.

Deeper SLP chapter 3, sections 3.1–3.6

DSA · Sparse nested maps

counts[context][token] is a hash map of hash maps. Most (context, token) pairs never occur, so you store only the ones that do. logprobs fills a dense vector with the smoothed default, then overwrites the few seen entries: O(V + seen), not O(V) dictionary lookups.

Watch out
  • Without k · V in the denominator, probabilities no longer sum to 1. A test catches that in one line.
  • Smoothing spreads mass over every token. Inside a JSON string, that mass is how a model wanders into junk (section 12).
Read more
  • Jurafsky and Martin, Speech and Language Processing, chapter 3: N-gram Language Models
06 · PERPLEXITY
ML5 min

How surprised is the model, on average?

Perplexity is exp(average negative log-probability) on held-out text. A model that guesses uniformly over V tokens has perplexity exactly V. Lower is better: "as confused as choosing among this many tokens".

ppl = exp( -(1/N) · Σ log P(token_i | context_i) )

NGramLM(2, 300).perplexity([[1, 2, 3, 4]]) == 300    # untrained → uniform → V
AskBefore running: will a 4-gram beat a 3-gram on held-out records? Write your guess in SPEC.md, then measure.
Fundamentals behind this section
ML · Entropy and cross-entropy

Entropy H(p) = −Σ p log p is the average surprise of a distribution. Cross-entropy H(p, q) is the average surprise when reality is p but you predict with q; it is always ≥ H(p), and the gap is the KL divergence. Perplexity is just ecross-entropy: the effective number of choices.

Deeper Visual Information Theory · 3Blue1Brown, Solving Wordle using information theory

Practice the token-tax study: tokens per sentence on FLORES+ (the same sentences in 200+ languages), with a paired bootstrap 95% interval for the Hindi/English ratio.

ML · Generalization

Perplexity on training text always improves with bigger n; on held-out text it improves, then gets worse as contexts become too rare to count. That U-shape is overfitting, and you will meet it in every model this program builds.

Watch out
  • Perplexity per token cannot compare tokenizers with different vocabularies. Use bits per byte.
  • Take the held-out split before training the tokenizer, or the test text leaks into the vocabulary.
07 · SOFTMAX AND TEMPERATURE
MLAI8 min

From scores to probabilities, without overflow

Softmax turns scores into probabilities: exponentiate, then divide by the total. Temperature divides the scores first. Low temperature sharpens toward the top token; high temperature flattens toward uniform.

def log_softmax(x):
    m = max(x)                                        # the stability trick
    if m == -inf: raise ValueError("every token is masked")
    lse = m + log(sum(exp(v - m) for v in x))         # exp(v - m) ≤ 1: never overflows
    return [v - lse for v in x]

probs = softmax([v / T for v in logits])              # T → 0: argmax.  T → ∞: uniform.

Subtracting the max changes nothing mathematically, because softmax(x + c) = softmax(x), but exp(1000) overflows a float and exp(0) does not.

Fundamentals behind this section
ML · Softmax and log-sum-exp

Softmax maps any real vector to a probability vector and keeps the order. Its log, log-softmax, is what models actually return, because adding log-probabilities is safer than multiplying probabilities (products of many small numbers underflow to 0).

Temperature T divides the logits: entropy rises with T, from 0 bits (argmax) toward log2V (uniform).

Deeper The Log-Sum-Exp Trick (Gregory Gundersen)

AI · What "temperature" in an API means

The temperature parameter in every LLM API is this division. Temperature 0 is greedy decoding; most providers then still differ run to run because of batching and floating-point order, not sampling.

08 · TOP-K, TOP-P, THE DRAW
DSAML7 min

Cut the tail, then draw one

Top-k keeps the k best tokens. Top-p keeps the smallest set of best tokens whose probability adds up to at least p, so it keeps few tokens when the model is sure and many when it is not. Then draw one token in proportion to what is left.

def top_k_filter(x, k):                               # heap of size k: O(V log k)
    keep = set(heapq.nlargest(k, range(len(x)), key=lambda i: (x[i], -i)))
    return [v if i in keep else -inf for i, v in enumerate(x)]

def top_p_filter(x, p):
    probs = softmax(x)
    order = sorted(range(len(x)), key=lambda i: (-probs[i], i))
    keep, mass = set(), 0.0
    for i in order:
        if mass >= p: break                           # check BEFORE adding: keep the token that crosses p
        keep.add(i); mass += probs[i]
    return [v if i in keep else -inf for i, v in enumerate(x)]

def categorical(probs, rng):                          # prefix sums + binary search
    prefix = list(itertools.accumulate(probs))
    return bisect.bisect_right(prefix, rng.random() * prefix[-1])

Fundamentals behind this section
DSA · Selection, prefix sums, binary search

Top-k is the selection problem: a size-k heap gives O(V log k); quickselect gives O(V) on average. The draw is inverse-CDF sampling: build prefix sums once, pick a uniform number u, and binary-search for the first prefix > u. bisect_right is exactly that search.

Practice LC 215 · Kth Largest LC 528 · Random Pick with Weight LC 704 · Binary Search LC 35 · Search Insert Position

ML · Truncating a distribution

Top-k and top-p remove the long tail, where a model's probabilities are least reliable, then renormalize. Top-p adapts: when the model is confident it keeps 1–2 tokens; when it is unsure it keeps many.

Practice test your sampler like a statistician: draw 10,000 tokens and run a chi-square goodness-of-fit test against softmax(logits / T). A correct sampler passes about 95% of the time at α = 0.05; a planted off-by-one fails every time.

09 · GREEDY AND BEAM
DSAAI5 min

The best next token is not always on the best path

Greedy takes the top token every step. Beam search keeps the B best partial sequences by total log-probability, extends each by every token, and keeps the B best again. Width 1 is greedy; a wide enough beam is exhaustive search.

beams = [(0.0, [])]
for _ in range(steps):
    candidates = []
    for score, seq in beams:
        lp = model.logprobs(prompt + seq)
        candidates += [(score + lp[t], seq + [t]) for t in range(len(lp))]
    beams = heapq.nsmallest(width, candidates, key=lambda c: (-c[0], c[1]))   # best first

Example: greedy picks "the" (0.5) then "cat" (0.3): 0.15. Another path, "a" (0.4) then "dog" (0.9), gives 0.36. Greedy never saw it.

Fundamentals behind this section
DSA · Best-first search with a bounded frontier

Beam search is breadth-first search that keeps only the best B nodes per level, chosen with a heap. Width 1 is greedy; unbounded width is exhaustive search over Vn sequences. The same "heap over frontiers" shape solves k-way merge and k-smallest-pairs.

Practice LC 373 · Find K Pairs with Smallest Sums LC 23 · Merge k Sorted Lists

ML · Sequence probability in log space

P(sequence) = Π P(token | prefix), so log P = Σ log P. Scores only go down as sequences grow, which is why beam search favours short outputs unless you add a length penalty.

Watch out
  • Beam search favours short, bland text in open-ended writing. It suits tasks with one right answer (translation, extraction).
  • Test it against brute force: with V = 4 and 3 steps, a beam of 64 must find the exact best.

10 · JSON AS AN AUTOMATON
DSAAI10 min

A state machine with a stack decides what may come next

To guarantee valid JSON, you need to know, after any prefix, which bytes may come next. A finite state machine handles one level (inside a string, inside a number). Nesting needs memory of what is open, so add a stack. That is a pushdown automaton.

State = (mode, aux, stack)        # immutable tuple → hashable → cacheable
#  mode:  START, VALUE, KEY, COLON, AFTER, STR, NUM, LIT, DONE, ...
#  aux:   detail inside a mode (number DFA state, escape progress, UTF-8 bytes left)
#  stack: ("o", "a", "o") = inside an object, inside an array, inside an object

def step(state, b):
    mode, aux, stack = state
    if mode == COLON:
        return (VALUE, None, stack) if b == ord(":") else None
    if mode == AFTER:                                  # just finished a value
        if b == ord(","):
            return (KEY, None, stack) if stack[-1] == "o" else (VALUE, None, stack)
        return close(stack, b)                         # } or ] must match the top of the stack
    if mode == NUM:
        nxt = number_dfa(aux, b)
        if nxt is not None: return (NUM, nxt, stack)
        if aux not in ACCEPTING: return None           # "1." or "-" cannot end here
        return step(after_value(stack), b)             # this byte belongs to what follows

Fundamentals behind this section
DSA · Stacks and automata

A finite automaton is a set of states and a transition table: enough for numbers, strings and literals. It cannot count, so it cannot match nested brackets. Add a stack and you get a pushdown automaton: push on { or [, pop on the matching close. Regular expressions ⊂ context-free grammars, exactly as finite automata ⊂ pushdown automata.

Design · Make invalid states unrepresentable

Retrying until the JSON parses is a loop with no bound. A mask makes invalid output impossible by construction: the system cannot reach the bad state at all. Prefer constraints you can prove over checks you hope pass.

Watch out
  • JSON's whole grammar fits on two pages of RFC 8259: read it before coding, and turn each rule into a test.
  • Make states immutable. If step mutates a shared stack, masking one branch corrupts the next.
  • Bound the depth (32). Otherwise the state space, and the cache, is unbounded.

11 · MASKING WITH A TRIE
DSASoftware Delivery7 min

Reject thousands of tokens with one byte

The mask needs every token that keeps the prefix valid. Checking each of 50,000 tokens separately repeats work, because tokens share prefixes. Put all tokens in a trie and walk it with the automaton: when a byte is rejected, the whole subtree under it is rejected too.

def allowed(state):
    if state in cache: return cache[state]               # states repeat constantly
    out, todo = [], [(trie.root, state)]
    while todo:
        node, s = todo.pop()
        for byte, child in node.children.items():
            s2 = step(s, byte)
            if s2 is None: continue                      # prune: no token below can be valid
            out.extend(child.tokens)                     # tokens can end at inner nodes ("a", "ab")
            if child.children: todo.append((child, s2))
    cache[state] = sorted(out)
    return cache[state]

The trie wins when few tokens fit. Inside strings, nearly every token fits, so there is little to prune. Production engines precompute most of the mask per grammar position and only check the few tokens that depend on the stack. That is XGrammar's main idea.

Fundamentals behind this section
DSA · Tries and pruned search

A trie stores strings by their shared prefixes: one node per prefix, one edge per next character (here, byte). Walking it with depth-first search and stopping at the first invalid byte skips every token below that node at once. A token can end at an inner node ("a" and "ab"), so collect ids at every node, not only leaves.

Masks are a pure function of the state, so they can be cached: the hit rate is about 99%. Bound the cache. Going further, split the work into what depends only on the grammar position (precompute once) and what depends on the stack (compute per request).

12 · THE CONSTRAINED LOOP
AIML5 min

Mask, renormalize, sample: invalid becomes impossible

Before each draw, set every disallowed token to −inf. Softmax renormalizes over what is left. Every prefix is now valid by construction, and generation stops when the automaton reaches DONE.

state = constraint.start()
for _ in range(max_new_tokens):
    if constraint.is_done(state): break
    logits = model.logprobs(ids)
    ok = constraint.allowed(state)
    masked = [-inf] * len(logits)
    for t in ok: masked[t] = logits[t]
    t = sampler(masked, rng)
    state = constraint.advance(state, t)
    ids.append(t)

Fundamentals behind this section
ML · Masking is conditioning

Setting invalid logits to −inf and renormalizing gives P(token | token is valid): Bayes' rule with a 0/1 likelihood. The relative odds of the valid tokens are unchanged; the mass the model put on invalid ones is spread over the rest in proportion.

AI · Structured outputs in practice

"JSON mode" and "structured outputs" in LLM APIs, Outlines, XGrammar and llama.cpp grammars all run this loop. A JSON Schema compiles to a grammar; the grammar compiles to an automaton; the automaton masks logits.

Watch out
  • Valid is not correct. The mask guarantees syntax, never that "priority" is right.
  • Hitting max_new_tokens mid-string leaves unfinished JSON. Decide in your spec what the caller gets.
  • The model was never asked; its probabilities were edited. A model that strongly wants an invalid token may produce odd valid text instead.

Design tok-serve: structured output as a service

Put the whole week together as one system and defend it with numbers: a service that takes a ticket and a JSON shape, and returns a record that is guaranteed to parse, for 10,000 requests a second.

Requirements

  • Functional: POST /extract {ticket, grammar} → JSON that parses, every time. English and Hindi.
  • Scale: 10,000 requests/s at peak, about 150 output tokens each, so 1.5 million masked decoding steps a second.
  • Latency: the mask adds at most 1 ms per step at p99, or it dominates generation.
  • Reliability: a retried request must not create a second record.

Can the mask keep up?Brute force on GPT-2's vocabulary: 10–56 ms per step. Trie: 0.2 ms at structural states, 33 ms inside strings. Too slow inside strings without precomputing per mode (XGrammar's split), plus the cache.

The design principles, and where you used each one

  1. Contracts at every boundary. Tokenizer, LanguageModel, Constraint are Protocols; any model or grammar that meets them plugs in. (13)
  2. Make invalid states unrepresentable. Mask instead of retry: invalid JSON cannot be produced. (12)
  3. Immutable, hashable state. Safe to branch in the trie walk, and cacheable by key. (10)
  4. Precompute what does not change; cache what repeats. The trie, the chunk cache, the mask cache. (11, 04)
  5. Incremental over recompute. Update only what a change touches. (03)
  6. Determinism. Tie-breaks in the spec, seeds for every random draw, versioned formats. Reproducible ids and outputs. (02, 08)
  7. Bound everything. Nesting depth, cache size, tokens per request. Unbounded inputs become outages. (10)
  8. Measure before optimizing. The trie is 55× faster in one place and 1.7× in another: only measurement tells you where to spend effort. (11)
